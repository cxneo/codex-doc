# 课程导读｜怎么学、怎么练、怎么验收

你不需要先成为 Codex 专家，也不需要背完所有命令。开始这套课程前，只要会使用 Android Studio、Git 和 Gradle Wrapper，并愿意把“我觉得做完了”改成“这是可以复现的完成证据”。

## 这套课程解决什么问题

想象一个常见场景：产品希望待办列表支持筛选。你让 AI “加三个筛选按钮”，几分钟后页面能显示了，但筛选在重启后丢失，完成任务时列表没有更新，测试没有覆盖 Room 数据，评审者也不知道 AI 修改了哪些边界。

问题不在于代码生成得不够快，而在于项目没有给执行者一条完整路线：

```text
业务意图
  → 可验证的 Spec
  → 带取舍和风险的 Plan
  → 可独立验收的 Tasks
  → RED / GREEN / REFACTOR
  → 审查、CI 与完成报告
```

课程会用 PocketTasks 把这条路线走一遍。Codex 是执行和协作工具，Android 工程规则、产品决定和最终责任仍由团队掌握。

## 开始前的三个约定

### 约定一：先调查，再修改

第一次进入项目时，先让 Codex 只读回答模块、数据流、构建命令和未知项。若连事实源在哪里都没有确认，任何“直接实现”都可能只是幸运。

### 约定二：一次只练一个新能力

练 AGENTS.md 时不要同时安装五个 MCP；练 TDD 时不要顺便改架构。变量越少，越能看清某个机制是否真正有用。

### 约定三：用证据完成，不用语气完成

完成报告至少区分四种状态：已经运行且通过、已经运行但失败、因条件不足未运行、明确不在本次范围。Codex 说“应该没问题”不属于证据。

## 先做环境体检

进入配套项目：

```bash
cd 配套文件/PocketTasks-codex
./gradlew --version
./gradlew :app:testDebugUnitTest
./gradlew :app:lintDebug :app:assembleDebug
```

如果 Gradle 找不到 Java，确认使用 JDK 17。若依赖下载失败，先检查组织代理、仓库镜像和网络策略，不要用删除锁文件、降低安全设置或随意升级版本来掩盖问题。

有设备或模拟器时：

```bash
adb devices
./gradlew :app:connectedDebugAndroidTest
```

没有设备也可以完成绝大多数章节，但必须把设备测试写为“未运行”。

## 五条学习路线

### 路线 A：Android 开发者第一次使用 Codex

按开篇、01～06、17～20 阅读。你的最小毕业产物是：

1. 一份带文件路径的只读调查结果；
2. 一次范围受控的 Android 修改；
3. 一条先失败、后通过的测试；
4. 一份列出已运行和未运行项的完成报告。

### 路线 B：技术负责人搭建项目工作流

顺序完成 01～10、16～22。重点不是为仓库塞满配置，而是决定哪些信息属于 AGENTS.md、哪些属于项目宪法、哪些必须由测试或 CI 强制执行。

### 路线 C：研发效能或平台团队

重点阅读 08～16、21。每引入 Rules、Hooks、MCP、Skill 或 Subagent，都要回答：触发条件是什么、权限边界是什么、失败时怎样被看见、维护者是谁、如何删除。

### 路线 D：从 Claude Code 或 Cursor 迁移

先读 23 或 24，不要先改文件。完成资产盘点和行为映射后，只选择一个低风险 Android 仓库试点，再按 06、09～15 补齐差异。

### 路线 E：团队讲师

使用[讲师手册](讲师手册.md)组织六次课程。每次课都应有现场演示、学员操作、故障注入和复盘，不建议只做幻灯片宣讲。

## 怎样做练习

课程提供三个可逆的故障实验。不要在有未提交业务改动的目录里应用补丁，最好创建练习分支或 Worktree。

```bash
cd 配套文件/PocketTasks-codex
./scripts/lab-patch.sh check 19-tdd
./scripts/lab-patch.sh apply 19-tdd
# 完成练习后，如需恢复基线
./scripts/lab-patch.sh reverse 19-tdd
```

另两个实验是 `20-review` 和 `22-migration`。每个实验目录都有 README。补丁脚本同时支持本课程嵌套仓库布局和独立复制后的项目布局。

## 怎样验收自己

读完一讲后，用下面四个问题自检：

1. 我能否不用原文解释这个机制解决了什么风险？
2. 我是否在 PocketTasks 或自己的项目里留下了一个可见产物？
3. 另一位同事能否按我的命令复现结果？
4. 我是否如实写出了没有验证的部分？

若第四题答不上来，先不要继续增加自动化。最后使用[结课实践](结课实践.md)完成一次独立闭环。

## 卡住时的排查顺序

先判断卡在哪一层：

```text
课程文件 → 环境/JDK/SDK → Git 现场 → Codex 配置 → Android 代码 → 设备环境
```

- 课程链接或配置不确定：运行 `ruby 配套文件/validate-course.rb`；
- Gradle 失败：先运行 `./gradlew --version`，再看第一处根因；
- Codex 行为不符合预期：确认项目信任、有效配置、AGENTS.md 与当前工作目录；
- Rules 或 Hooks 不生效：先做独立黑盒测试，不要依赖聊天中的主观观察；
- 设备测试失败：分别检查 `adb devices`、模拟器 API、安装和测试报告。
