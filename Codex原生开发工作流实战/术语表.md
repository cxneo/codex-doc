# 术语表

这份表不是产品功能清单，而是课程中的统一用词。团队把教程迁入自己的仓库时，可以保留定义，替换 PocketTasks 相关示例。

## Codex 与工作流

| 术语 | 本课程中的含义 | 容易混淆的地方 |
|---|---|---|
| Agent | 能读取上下文、调用工具、修改文件并验证结果的执行者 | 不等于不受约束的“全自动开发者” |
| Task / 任务 | 有目标、边界、执行过程和结果的一段工作 | 在不同 Codex 界面中也可能称 thread 或 conversation；课程不把它与 `tasks.md` 的实施任务项混为一谈 |
| Turn / 轮次 | 用户输入到 Codex 返回结果的一次交互 | 一个任务可以包含多轮 |
| Context / 上下文 | 当前轮可用于推理的指令、文件、对话与工具结果 | “仓库里存在”不等于“已经进入有效上下文” |
| Prompt / 提示 | 针对当次目标的自然语言输入 | 不适合承载长期团队规则 |
| AGENTS.md | Codex 读取的项目级长期指令 | 对应 Claude Code 的 `CLAUDE.md` 只是概念映射，加载和优先级应按 Codex 规则验证 |
| Memory / 记忆 | Codex 在任务间保留的经验性信息 | 不替代可评审、可版本化的 AGENTS.md；课程默认把关键团队知识写入仓库 |
| Goal / 目标 | 长任务中的持续目标与进度状态 | 不是 Spec，也不是承诺自动满足业务验收 |
| Spec | 描述系统必须呈现的可观察行为、范围和未知项 | 不等于界面清单或技术方案 |
| Plan | 把 Spec 映射到组件、数据流、风险和验证策略 | 不应在没有仓库调查时凭空生成 |
| Tasks | 按依赖排列、可以独立验证的实施动作 | 不等于把 Plan 拆成几句话 |
| Evidence / 证据 | 能被他人复现的测试、命令、报告、截图或人工步骤 | Codex 的总结和“理论上可行”不算证据 |

## 安全与执行

| 术语 | 本课程中的含义 | 容易混淆的地方 |
|---|---|---|
| Trust / 项目信任 | 允许加载项目级 Codex 配置的信任判断 | 信任仓库不代表仓库中的每条命令都安全 |
| Sandbox / 沙箱 | 限制文件系统、网络和进程能力的执行边界 | 不是权限规则的同义词 |
| Approval / 审批 | 在某项动作执行前要求人确认 | 不应成为高风险动作唯一防线 |
| Rules | 根据命令前缀等规则允许、提示或禁止执行 | 规则要通过真实命令匹配测试，不能只靠阅读判断 |
| `codex execpolicy` | 用于检查执行策略匹配的预览能力 | 预览能力的接口可能变化，升级后需重测 |
| Permission profile | 桌面应用中的权限配置组合 | 当前属于 beta 能力；不要与传统 `sandbox_mode` 配置混写后假设优先级 |
| Hook | 在 Codex 生命周期事件发生时执行的处理器 | Hook 是自动执行代码；必须审查输入、超时、失败模式和信任边界 |
| Fail closed | 输入异常或判断失败时拒绝高风险动作 | 不是所有辅助型 Hook 都必须拒绝；要按风险选择 |

## 扩展与自动化

| 术语 | 本课程中的含义 | 容易混淆的地方 |
|---|---|---|
| MCP | 让 Codex 连接外部数据和动作的开放协议 | 连接成功不代表最小权限、数据合规和审批已经解决 |
| App | 在 Codex 中使用的已连接应用能力 | 与 Android `Application`、手机 App 不是同一个概念 |
| Plugin | 打包 Skills、MCP/App 等能力的可安装单元 | 课程讨论 Codex Plugin 时不沿用 Claude Plugin 的文件结构 |
| Skill | 带触发描述、说明和可选资源的可复用专家方法 | 不是一句保存下来的 Prompt；要能测试触发和结果 |
| Subagent | 为具体子任务创建的独立协作者/上下文 | 不适合把强依赖、同文件写入任务盲目并行 |
| Custom agent | 通过项目或个人配置定义的专门 Agent 角色 | 文件格式和可用字段可能随产品演进，升级需复核 |
| Worktree | 同一 Git 仓库的独立工作目录 | 隔离文件现场，不消除业务语义冲突 |
| Handoff / 交接 | 把任务现场、结论、证据和未决项交给另一个界面或成员 | 不能只写“已完成”，要包含工作目录和验证状态 |
| `codex exec` | 非交互执行 Codex 任务的 CLI 入口 | 默认只读；进度与最终输出通道不同，CI 应使用结构化输出和明确 Schema |
| SDK | 以编程方式集成 Codex 的开发接口 | 不等于直接复制 CLI 文本输出做脆弱解析 |
| Action | 在 GitHub Actions 等自动化环境中调用 Codex 的集成 | 常规 Android CI 和 AI 审查/修复应分开设计权限与触发条件 |
| Scheduled task | 由 Codex 桌面或 Web 管理的定时任务 | 本地执行依赖机器与应用环境；不能假设 CLI/Android Studio 中有同一管理入口 |
| Computer Use | Codex 操作图形界面的能力 | 可用性受平台、区域和组织策略影响；Android 设备断言仍需测试证据 |

## Android 示例

| 术语 | 本课程中的含义 |
|---|---|
| UI State | Compose 渲染的不可变界面状态 |
| 单向数据流 | 事件向下传递，状态从事实源流回 UI |
| 事实源 | 对某类状态具有最终权威的数据来源；PocketTasks 的任务数据由 Room 持有 |
| DataStore | 保存筛选偏好等小型持久化设置 |
| Room Migration | 已发布数据库 Schema 的显式升级路径 |
| JVM 测试 | 不依赖 Android 设备运行的本地测试 |
| AndroidTest | 在设备或模拟器上运行的仪器测试 |
| AndroidTest 编译 | 只证明测试 APK 能构建，不证明测试在设备上执行成功 |
| Gradle Wrapper | 仓库固定的 Gradle 启动入口 `./gradlew`；课程不依赖全局 Gradle |

如果一个词在产品界面中发生变化，以[版本与兼容性](版本与兼容性.md)和官方文档为准，并在团队材料中记录采用的新名称。
