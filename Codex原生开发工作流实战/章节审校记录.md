# 章节审校记录

本记录回答用户最关心的问题：相对 Claude Code 官方文档与《AI 原生开发工作流实战》的内容组织方式，Codex 教程每一讲是否覆盖了对应能力，哪些地方已经细化，哪些地方以后仍需随产品更新复核。

审校基线为 2026-08-06。Codex 事实以官方文档和本地黑盒验证为主；Claude Code 仅用于发现主题覆盖与迁移差异，不用来推断 Codex 的命令或配置。

## 审校方法

每一讲从五个角度检查：

1. **问题感**：先出现真实 Android 场景，而不是从配置键开始；
2. **边界**：说明机制解决什么、不解决什么；
3. **对应关系**：相似的 Claude 能力在 Codex 中怎样实现，哪里不能直译；
4. **可操作性**：有命令、文件或 PocketTasks 练习；
5. **完成证据**：读者知道怎样判断做对，以及哪些结论有时效性。

状态含义：**已验证**表示配套命令或项目行为已实际运行；**已细化**表示事实和练习已补齐，但外部服务/组织环境需要使用者自行验证；**需持续复核**不是当前缺陷，而是产品更新敏感项。

## 仍然不应该写死的结论

以下内容刻意没有包装成永久事实：

- Codex 的 Slash 命令、桌面 UI 名称和 IDE 支持范围；
- beta / preview 能力的配置格式；
- Hooks 事件和可执行处理器类型；
- Memories、Scheduled tasks、Computer Use 的可用范围；
- Claude Code 与 Cursor 持续演进后的完整资产格式；
- “推荐 Android 架构”在具体项目中的唯一实现。

维护者每季度或重大版本升级后，应按[版本与兼容性](版本与兼容性.md)重新验证，并把结论写入 [CHANGELOG](CHANGELOG.md)。

## 审校结论

24 讲已经形成“场景—边界—操作—证据—时效点”的完整链路。相对 Claude 参考材料，Codex 教程当前不缺主要主题；真正需要持续投入的是产品时效复核和组织环境验证，而不是继续堆叠未经运行的功能清单。
