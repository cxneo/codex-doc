# 版本与兼容性

本页回答两个问题：这套课程在哪个基线上验证过，以及产品更新后应该先复查什么。它不是“永远锁死版本”的要求。

## 最近验证基线

验证日期：2026-08-06。

| 组件 | 课程基线 | 说明 |
|---|---|---|
| Codex CLI | 本机验证 `0.147.0-alpha.1.2` | 课程不要求同事安装完全相同的 alpha 构建；命令和配置应以安装版本的官方文档/帮助为准 |
| Android Gradle Plugin | 8.9.2 | 配套工程可复现基线 |
| Kotlin | 2.0.21 | 与 Compose 编译插件配置一起验证 |
| Gradle Wrapper | 8.11.1 | 使用仓库内 `./gradlew` |
| compileSdk / targetSdk | 35 | 需要 Android SDK Platform 35 |
| JDK | 17 | CI 与本地教学基线 |
| Python | 3.11+ | 校验 TOML 和运行 Hook 黑盒测试；旧版本可安装 `tomli` 兼容 |
| 仪器测试 | API 35 模拟器 | Compose 测试与 Room v1→v2 Migration 测试 |

配套项目为中国大陆培训环境配置了阿里云 Google/Public 镜像，并保留官方仓库作为后备。组织有供应链限制时，应改用批准的内部代理或官方仓库，并单独验证依赖来源。

## Codex 能力的课程处理方式

| 能力 | 当前课程怎么处理 | 升级时先复查 |
|---|---|---|
| CLI、登录、AGENTS.md、`codex exec` | 作为核心路径讲解，并提供真实项目练习 | 安装方式、Slash 命令、配置键、输出通道 |
| Codex 桌面应用与 Worktrees | 讲管理式 Worktree、交接和本地环境 | UI 名称、Worktree 创建/清理行为、`.worktreeinclude` |
| 官方 IDE 扩展 | 只陈述 VS Code 兼容编辑器路径 | 是否新增官方 JetBrains / Android Studio 扩展；在确认前不要写“已支持” |
| Permission profiles | 按 beta 能力介绍 | Profile Schema、与 `sandbox_mode` 的关系、组织管理入口 |
| `codex execpolicy` | 按 preview 能力用于规则测试 | 命令名称、匹配语义、输出格式 |
| Hooks | 使用命令处理器并提供黑盒测试 | 事件名、输入/输出 JSON、超时、可执行处理器类型 |
| Skills | 使用 Agent Skills 目录结构 | 搜索路径、Frontmatter、触发与依赖声明 |
| Custom agents / Subagents | 展示只读调查与 Android 审查角色 | 配置文件格式、继承关系、并发限制和可用工具 |
| MCP、Apps、Plugins | 分别讲协议、连接能力和打包层 | OAuth、审批、组织允许列表、插件清单格式 |
| Memories | 说明默认关闭并强调仓库规则优先承载团队知识 | 默认值、存储位置、清理和组织策略 |
| Scheduled tasks | 说明由桌面/Web 管理，本地任务依赖机器和应用运行 | 管理入口、云端/本地运行条件、失败通知 |
| Computer Use | 作为条件能力，不作为必做练习 | 平台、区域、组织策略与可观测证据 |

课程示例的 `.codex/config.toml` 使用保守的传统沙箱配置，没有同时叠加 Permission profile。不要把两套机制混在一个复制粘贴示例中，再凭感觉解释哪一套生效。

## 验证课程文件

只检查文档链接与标题锚点、JSON/YAML/TOML 语法、Shell 脚本、Rules 决策、Hook 测试和三个故障补丁：

```bash
ruby 配套文件/validate-course.rb
```

同时运行 Android JVM 测试、Lint、Debug 构建和 AndroidTest APK 构建：

```bash
ruby 配套文件/validate-course.rb --android
```

脚本不会联网检查外部链接，也不会自动启动模拟器。设备测试必须单独执行：

```bash
cd 配套文件/PocketTasks-codex
adb devices
./gradlew :app:connectedDebugAndroidTest
```

## 升级时的最小流程

1. 创建独立分支或 Worktree；
2. 只升级一类基线，例如 Gradle/AGP 或 Codex 配置，不混入业务改动；
3. 运行课程校验脚本；
4. 重新执行 Rules 与 Hook 黑盒测试；
5. 应用并恢复三个故障补丁，确认实验仍能产生预期失败；
6. 有设备时运行 Compose 与 Migration 测试；
7. 更新本页验证日期、基线和 [CHANGELOG](CHANGELOG.md)；
8. 在评审中附“通过、失败、未运行、残余风险”四类结果。

## 常见兼容性问题

### Codex 中没有教程提到的命令

先运行本机帮助并查官方文档。不要用 Claude Code 或 Cursor 中相同名称的命令推断 Codex 行为；即使名称一致，参数、加载范围和安全语义也可能不同。

### Android Studio 能构建，命令行不能

通常是 JDK、SDK、代理或 `local.properties` 环境不同。先比较 Android Studio 使用的 Gradle JDK 与终端 `./gradlew --version`，不要直接修改工程版本。

### Worktree 缺少本地 SDK 配置

课程 `.worktreeinclude` 只复制被忽略的 `local.properties`。不要用它复制签名文件、生产密钥或账号配置。

### 设备测试显示“跳过”或找不到设备

`assembleDebugAndroidTest` 只是编译。只有 `adb devices` 有 `device` 状态目标，且 `connectedDebugAndroidTest` 成功，才能记录为设备测试通过。
