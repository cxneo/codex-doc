# 任务列表筛选 Spec

状态：Approved  
负责人：PocketTasks Team  
创建日期：2026-08-06

## 背景与用户问题

用户完成多项任务后，全部任务混在一个列表中，难以聚焦仍需处理的事项。用户需要在不修改任务数据和排序的前提下切换“全部 / 进行中 / 已完成”，并在下次打开应用时恢复最近选择。

## 目标

- 提供三个互斥筛选项：全部、进行中、已完成。
- 在 Activity 重建与应用冷启动后恢复最近选择。
- 当前筛选随 Room 任务数据变化即时更新。
- 提供可理解、可访问的筛选与空状态。

## 非目标

- 不增加账户、云同步或跨设备偏好同步。
- 不改变任务排序、删除、编辑或完成语义。
- 不增加标签、日期筛选或搜索。
- 不修改 Task Entity、DAO 或 Room Schema。
- 不新增埋点和深链。

## 用户场景

### 场景一：查看进行中任务

Given 同时存在进行中与已完成任务  
When 用户选择“进行中”  
Then 列表只显示进行中任务  
And 原有排序保持不变  
And 筛选不修改任何任务数据

### 场景二：完成当前可见任务

Given 当前筛选是“进行中”  
And 列表包含任务“准备周报”  
When 用户将该任务标记为完成  
Then 持久化状态变为已完成  
And 它立即从当前列表消失  
And 切换到“已完成”后可以看到它

### 场景三：恢复最近选择

Given 用户已经选择“已完成”  
When Activity 重建或应用冷启动  
Then 筛选仍为“已完成”

Given 用户从未选择过  
When 首次启动  
Then 默认显示“全部”

### 场景四：区分空状态

Given 数据库中存在任务，但当前筛选没有匹配项  
Then 显示“当前筛选下没有任务”并提供返回“全部”的操作

Given 数据库完全没有任务  
Then 继续显示已有的首次创建引导

## 验收标准

- [ ] 三种筛选只影响可见集合，不改变任务与排序。
- [ ] 完成任务后，当前筛选列表由 Room 事实源重新派生。
- [ ] 筛选跨 Activity 重建和冷启动恢复；首次默认 ALL。
- [ ] 读取未知或损坏偏好值时回退 ALL，任务仍可使用。
- [ ] 写偏好失败时，本次会话仍能切换，错误按现有通道处理。
- [ ] 控件暴露文本、角色与选中语义，不只靠颜色表达。
- [ ] 两类空状态可区分，大字体和横屏下主要操作可用。

## Android 质量影响

- 生命周期：需要跨进程持久化，不只依赖 Compose 保存状态。
- 数据：Room 继续保存任务，DataStore 只保存筛选偏好。
- 协程：组合任务 Flow 与筛选 Flow，测试使用可控调度器。
- 权限：无新增权限或后台工作。
- 无障碍：三个选项有选中语义，空状态操作有可读标签。

## 异常与回退

- 读取失败或未知值：使用 ALL，不影响任务读取。
- 写入失败：保留本次会话选择，报告非阻断错误。
- 任务数据读取失败：沿用现有 Tasks 错误状态，不用空状态掩盖。
