# 04｜环境搭建：安装、登录与第一次安全会话

上一讲画出了 Codex 的系统地图。这一讲不追求“把所有开关都配好”，只完成一条最小闭环：让 Codex 进入一个 Android 仓库，先调查，再做一个可控改动，最后用 Gradle 证明结果。

## 开始之前：先确认 Android 工程自己能跑

AI 无法修复一个连基线都不清楚的环境。进入项目根目录，先由你自己执行：

```bash
./gradlew --version
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest
```

如果项目不是 `app` 模块，请替换模块名。如果基线已经失败，把失败命令和原因记下来；不要让 Codex 把历史问题误认成这次改动造成的回归。

设备端测试还需要已连接的设备或已启动的模拟器：

```bash
adb devices
./gradlew :app:connectedDebugAndroidTest
```

第一次学习时不必强求设备测试全部通过，但必须知道它需要额外运行环境，不能把“没跑”写成“已通过”。

## 安装 Codex CLI

常见安装方式是：

```bash
npm install --global @openai/codex
codex --version
```

然后登录：

```bash
codex login
codex login status
```

登录流程会引导你选择 ChatGPT 账户或 API Key。团队机器、个人电脑与 CI 的凭据管理方式不同，不要把 Token 写进仓库、AGENTS.md 或示例脚本。

产品安装方式可能变化。如果命令和你本机版本不一致，请以 [Codex 官方安装文档](https://developers.openai.com/codex/cli/) 为准。

## 第一次进入项目

在 Android 项目根目录启动：

```bash
codex
```

先使用只读任务，不要一上来就说“优化整个项目”：

```text
先不要修改任何文件。
请识别这个 Android 项目的模块、应用入口、UI 技术、状态管理、数据层、
本地测试、仪器测试与构建命令。
每个结论给出对应文件路径；不确定的地方明确标为未知。
```

这段请求有三个安全设计：限定只读、要求证据、允许承认未知。一个可靠协作者不应为了显得完整而猜测。

## 认识审批与沙箱

Codex 能执行 Shell，也就可能运行会下载依赖、写入大量文件、修改 Git 状态甚至访问外部服务的命令。审批策略决定何时需要人确认，沙箱决定即使命令被执行，它能触达什么范围。

第一次会话建议保持保守设置。可以在会话中使用 `/permissions` 查看或调整当前权限。遇到请求批准时，不要只看“允许 / 拒绝”，而要读清：

- 命令究竟是什么；
- 工作目录在哪里；
- 是否访问网络；
- 会写哪些路径；
- 是否有更小的等价命令。

例如 `./gradlew :app:testDebugUnitTest` 会写 `build/` 并可能首次下载依赖，这是正常工程行为；而一条递归删除命令或不明安装脚本，应当停下来核实目标。

## 做一个最小改动

调查完成后，选择无业务风险的小任务，例如修正一个测试名称或 README 中的过时命令。请求可以这样写：

```text
请修正 README 中已经过时的单元测试命令。
先验证当前 Gradle task 名称，只修改相关文档；
完成后展示 diff，并运行不会改动源码的验证命令。
不要顺手格式化其他文件。
```

随后用 `/diff` 查看改动。如果任务涉及代码，再运行最窄的目标测试，然后视风险扩大到：

```bash
./gradlew :app:testDebugUnitTest
./gradlew :app:lintDebug
./gradlew :app:assembleDebug
```

验证顺序从快到慢，可以让失败更早暴露，也避免每一次小修改都等待全量构建。

## 一次会话的标准收尾

不要以“Codex 说完成了”作为结束。让它给出结构化摘要：

```text
请用四部分总结：
1. 修改了什么，以及对应文件；
2. 为什么这样修改；
3. 实际运行了哪些验证，结果是什么；
4. 哪些验证未运行、仍有什么风险。
```

然后你自己检查 diff 与关键测试结果。这里建立的是后面每一讲都会复用的节奏：

```text
先调查 → 定边界 → 小步修改 → 运行验证 → 检查 diff → 说明残余风险
```

## 常见问题

### Gradle 首次执行很慢，是 Codex 卡住了吗？

不一定。Gradle Wrapper、Android Gradle Plugin 和依赖可能正在下载。让 Codex 报告当前进程与最近输出，不要因为安静就重复启动多个构建。

### 能让 Codex 直接操作 Android Studio 吗？

Codex 可以从 IDE 扩展协作，也可以通过命令运行 Gradle 与 adb；但 Preview、Profiler 等图形工具仍适合由你查看。不要把“可执行命令”误解成“替代整个 IDE”。

### 应该固定课程中的模型名称吗？

不建议。可用模型和默认值会更新。团队应声明任务所需能力、风险和验证标准，模型选择则参考当前官方说明。

## 小结

第一次成功会话的标志不是生成了多少代码，而是你掌握了一个可复现的闭环，并且清楚哪些证据实际存在。

下一讲会拆开这段闭环最核心的机制：Codex 究竟怎样获得上下文，又怎样通过 Shell 把“理解”变成“行动”。
