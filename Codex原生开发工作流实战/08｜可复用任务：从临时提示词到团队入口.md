# 08｜可复用任务：从临时提示词到团队入口

前两讲把长期知识写进了 AGENTS.md 和项目宪法，但开发中的许多动作仍在重复：每次都要解释怎样写 Spec、怎样检查 Compose 状态、怎样汇报验证结果。

如果每个人各自保存一段提示词，团队最终会得到十个版本的“标准流程”。这一讲要做的，是把高频任务变成仓库中可发现、可版本化的入口。

## 先分清两类“斜杠命令”

Codex 自带许多会话命令，例如：

- `/plan`：切换到计划式协作；
- `/review`：启动代码审查；
- `/diff`：查看当前改动；
- `/status`：检查会话状态；
- `/permissions`：查看或调整权限；
- `/skills`：浏览和调用可用 Skills；
- `/compact`：压缩长会话上下文；
- `/agent`：查看或切换子 Agent 线程。

这些是产品能力，不是项目业务流程。网络上旧教程还可能介绍 Custom Prompts；当前 Codex 已把它列为弃用能力，新建团队入口应优先使用 Skills。

## 从任务模板开始，而不是急着造命令

在 PocketTasks 中，我们先为“功能澄清”定义一份模板：

```markdown
# 功能 Spec

## 背景与用户问题

## 目标

## 非目标

## 用户场景

## 验收标准
- [ ] Given ... When ... Then ...

## Android 影响面
- UI State / 生命周期：
- 数据与持久化：
- 权限 / 后台工作：
- 无障碍 / 本地化：

## 验证策略

## 未决问题
```

模板的价值不在空白标题，而在提醒团队问对问题。它可以直接放在 `specs/000-template/spec.md`，由人或 Codex 复制。

然后为 Codex 写一条稳定的调用说明：

```text
请按照 specs/000-template/spec.md 澄清下面的想法。
先调查现有实现，不修改产品代码；
无法从仓库确认的问题集中列出，不要自行编造业务答案；
验收标准必须可以映射到测试或人工验证。

想法：为任务列表增加进行中 / 已完成筛选。
```

在流程尚未稳定前，用模板加清晰请求比立即封装 Skill 更容易调整。

## 什么时候升级为 Skill

当一个流程满足三个条件时，就值得进入 Skill：已经重复成功多次、输入输出相对稳定、需要的不只是几句话而是步骤和配套资源。

例如 Android 代码审查需要读取 diff，识别 Compose、ViewModel、协程、Room 和权限风险，按严重程度输出，并运行适当检查。这已经是一套专家流程，适合放在：

```text
.agents/skills/android-code-review/
├── SKILL.md
└── references/
    ├── compose.md
    └── room.md
```

第 13 讲会完整制作这个 Skill。现在只需记住：模板统一产物形状，Skill 统一解决问题的过程。

## 为任务入口设计清晰契约

一个可靠入口至少说明五件事：

1. 何时使用，何时不要使用；
2. 必须读取哪些项目文件；
3. 执行步骤和停止点；
4. 预期产物放在哪里；
5. 结果怎样验证。

例如“生成实施计划”不能只有一句“帮我规划”。它要先读取已经批准的 Spec 和宪法，不得修改源码，必须列出文件影响面、依赖顺序、数据库与 UI 风险，并在未决问题影响方案时停止等待确认。

## 不要自动化尚未理解的流程

第一次做 Room 迁移时，团队可能还不知道最合适的 Schema 导出、升级测试和 CI 方式。此时过早封装，只会把一次偶然做法固化。

更稳妥的演进顺序是：

```text
手工协作一次
  → 复盘哪些步骤有效
  → 写成模板
  → 重复三到五次
  → 抽取稳定流程为 Skill
  → 用 Hook 或 CI 自动检查关键结果
```

工程化不是把所有事情自动化，而是只自动化已经理解的事情。

## 本讲实践：建立三个团队入口

在仓库中先建立三份简短模板：

- `spec.md`：描述行为、边界和验收；
- `plan.md`：描述技术路径、影响面、风险和验证；
- `tasks.md`：描述依赖顺序、文件、测试与完成状态。

然后选一个真实小需求，让两位同事分别使用这些模板与 Codex 协作。比较产物时，不评价文风，重点看：是否减少遗漏、是否更容易评审、是否能从验收标准追踪到测试。

## 小结

可复用任务的目标不是少打几行字，而是让团队对“怎样完成某类工作”形成共同入口。内置斜杠命令管理会话，模板稳定产物，Skills 封装成熟流程。旧式 Custom Prompts 不再适合作为新体系的中心。

现在，Codex 已经知道项目、原则和任务入口。能力越强，越要讨论边界。下一讲将进入安全基石：审批、沙箱与 Rules 如何共同限制它能做什么。
